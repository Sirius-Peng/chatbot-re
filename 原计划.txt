好的，我将基于你现有的 传讯WebApp 前端代码，设计一份完整的、可独立运行的全栈 WebApp 实现计划。这个计划将涵盖前端、后端（API + 管理后台）、数据库以及部署方案，同时保留你所有的前端设计风格。

## 📋 项目全景规划

### 🎯 目标

构建一个完整的、可独立运行的全栈 Web 应用，具备：
- 完整的用户系统（注册/登录/多设备同步）
- 后台管理面板（用户管理/内容管理/系统配置）
- 云端数据存储（聊天记录/设置/资源）
- 保留现有所有前端功能和设计风格

#### 1.2 数据库设计与搭建
- [ ] 安装配置 PostgreSQL
- [ ] 设计数据库 Schema：
  ```sql
  -- 用户表
  CREATE TABLE users (
    id UUID PRIMARY KEY,
    username VARCHAR(50) UNIQUE,
    email VARCHAR(100) UNIQUE,
    password_hash VARCHAR(255),
    avatar_url VARCHAR(500),
    created_at TIMESTAMP,
    updated_at TIMESTAMP
  );

  -- 角色/梦角表
  CREATE TABLE characters (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    name VARCHAR(100),
    avatar VARCHAR(500),
    greeting TEXT,
    voice_type VARCHAR(50),
    created_at TIMESTAMP
  );

  -- 聊天会话表
  CREATE TABLE chat_sessions (
    id UUID PRIMARY KEY,
    user_id UUID REFERENCES users(id),
    character_id UUID REFERENCES characters(id),
    title VARCHAR(200),
    created_at TIMESTAMP,
    updated_at TIMESTAMP
  );

  -- 消息表
  CREATE TABLE messages (
    id UUID PRIMARY KEY,
    session_id UUID REFERENCES chat_sessions(id),
    role VARCHAR(20), -- 'user' | 'assistant'
    content TEXT,
    message_type VARCHAR(20), -- 'text' | 'voice' | 'sticker'
    metadata JSONB,
    created_at TIMESTAMP
  );

  -- 用户设置表
  CREATE TABLE user_settings (
    user_id UUID PRIMARY KEY REFERENCES users(id),
    settings JSONB,
    updated_at TIMESTAMP
  );
  ```
- [ ] 创建数据库迁移脚本
- [ ] 编写种子数据脚本

#### 1.3 Redis 配置

#### 1.4 对象存储配置

## 🛠️ 技术栈推荐

### 后端
- **运行时**: Node.js 18+
- **框架**: Express.js 或 Fastify（推荐 Fastify，性能更好）
- **语言**: JavaScript 或 TypeScript（推荐 TypeScript）
- **ORM**: Prisma 或 TypeORM（推荐 Prisma）
- **认证**: jsonwebtoken + bcrypt
- **验证**: Joi 或 Zod
- **日志**: Winston 或 Pino

### 数据库
- **主数据库**: PostgreSQL 14+
- **缓存**: Redis 7+
- **对象存储**: MinIO（自托管）或 阿里云 OSS / 腾讯云 COS

### 前端
- **现有技术保留**: HTML5 + CSS3 + Vanilla JS
- **新增**:
  - API 请求库: Axios 或原生 Fetch
  - 状态管理: 保持现有模式（全局变量）
  - 路由: 保持无路由模式（单页应用）

### 部署
- **容器化**: Docker + Docker Compose
- **Web 服务器**: Nginx
- **CI/CD**: GitHub Actions
- **云服务**:
  - 自托管: VPS（阿里云/腾讯云）
  - 云服务: Vercel（前端）+ Railway/Render（后端）

## ⚠️ 注意事项

1. **渐进式迁移**: 保持前端现有功能可用，逐步替换为 API 调用
2. **向后兼容**: 保留本地存储作为离线缓存，确保离线可用
3. **数据安全**: 敏感数据（API Key、密码）必须加密存储
4. **性能考虑**: 使用分页、缓存、索引优化数据库查询
5. **扩展性**: 设计时考虑未来功能扩展（如多人聊天、语音通话等）
